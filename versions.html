Lesson 1: Paano Basahin ang Minecraft at Script API Version

Bago ka magsulat ng manifest.json, kailangan mong malaman kung anong Minecraft version ang target mo at kung anong module version ang kasama nito. Dalawang magkaibang numbering ang ginagamit natin:

🎮 Minecraft (game) version

Halimbawa: 1.26.50. Ito ang makikita mo sa game at sa CurseForge (madalas nakasulat na 26.50). Sa manifest, isinusulat ito bilang array sa min_engine_version:

"min_engine_version": [1, 26, 50]

📦 Script module version

Halimbawa: 2.10.0 para sa @minecraft/server. Hiwalay ang numbering nito at isinusulat bilang string sa dependencies:

{ "module_name": "@minecraft/server",
  "version": "2.10.0" }

🩹 Paano naman ang 1.26.52?

Ang pinakabagong release ay 1.26.52, pero karaniwang bug-fix (hotfix) lang ito ng 1.26.50 at gumagamit ng parehong script module versions. Kaya ang itinuturo natin sa lesson na ito ay 1.26.50 — gamitin ang [1, 26, 50] para gumana ang add-on mo sa 1.26.50 at sa 1.26.52.

Track Ibig sabihin Halimbawa
StableTapos na at ligtas gamitin. Walang suffix."2.10.0"
BetaBagong features na pwede pang magbago. May -beta sa dulo."2.11.0-beta"
PreviewHiwalay na Minecraft app para sa pag-test ng susunod na update.1.26.60 Preview

✅ Tip: Gamitin ang pinakamataas na stable

Inirerekomenda ng Microsoft na ibase ang dependency sa pinakamataas na stable version na supported ng Minecraft version na tina-target mo. Sa stable track, backwards-compatible ang mga minor versions (semantic versioning).

💻 Para sa VS Code (autocomplete)

I-install ang type definitions na tugma sa manifest mo:

npm i @minecraft/server-ui@2.2.0

Lesson 3: Anatomy ng manifest.json (Behavior Pack)

Ang manifest.json ang "ID card" ng pack. Dito nalalaman ng Minecraft kung ano ang pack mo, anong version ng game ang kailangan, at anong script modules ang gagamitin.

{
  "format_version": 2,
  "header": {
    "name": "Pinoy Legends BP",
    "description": "Custom weapons gamit ang Script API",
    "uuid": "11111111-aaaa-4bbb-8ccc-111111111111",
    "version": [1, 0, 0],
    "min_engine_version": [1, 26, 50]
  },
  "modules": [
    { "type": "data",
      "uuid": "22222222-aaaa-4bbb-8ccc-222222222222",
      "version": [1, 0, 0] },
    { "type": "script",
      "language": "javascript",
      "uuid": "33333333-aaaa-4bbb-8ccc-333333333333",
      "entry": "scripts/main.js",
      "version": [1, 0, 0] }
  ],
  "dependencies": [
    { "module_name": "@minecraft/server", "version": "2.10.0" },
    { "module_name": "@minecraft/server-ui", "version": "2.2.0" }
  ]
}
Field Para saan?
format_versionLaging 2 para sa modernong pack manifest.
header.uuidNatatanging ID ng buong pack. Bawat pack ay may sariling UUID.
header.versionVersion ng pack mo (array ng 3 numbers). Dagdagan ito kapag nag-update ka.
min_engine_versionPinakamababang Minecraft version na kayang magbukas ng pack mo.
modules[type=data]Nagsasabing may data (items, entities, recipes) ang Behavior Pack. May sariling UUID.
modules[type=script]Ang script module. entry ang unang JavaScript file na tatakbo; language ay laging "javascript".
dependenciesMga kailangang script module (module_name + version bilang string) o ibang pack (uuid + version bilang array).
⚠️ Mahalaga: Kailangang magkakaiba ang lahat ng UUID (header at bawat module). Huwag mag-copy-paste ng parehong UUID sa dalawang pack — gamitin ang Instant UUID v4 tool sa sidebar o ang generator sa Lesson 6.

Lesson 4: Stable vs Beta APIs at ang mga Pagbabago sa 2.x

🟢 Stable (hal. "2.10.0")

  • Hindi kailangan ng "Beta APIs" toggle.
  • Hindi nawawala ang Achievements — achievement-friendly.
  • Hindi basta-basta nasisira kapag nag-update ang Minecraft.

🟡 Beta (hal. "2.11.0-beta")

  • Kailangang i-on ang Beta APIs sa World → Experiments.
  • Naka-off ang Achievements sa world na iyon.
  • Pwedeng magbago o mawala ang API sa susunod na update.

Kung mali ang version sa dependencies (hal. wala sa Minecraft version mo), hindi mag-lo-load ang script at may lalabas na error sa Content Log (Settings → Creator → Content Log).

Ano ang nagbago mula 1.x papuntang 2.x?

Kung gumagamit ka ng @minecraft/server 2.x (tulad ng 2.10.0), ito ang mga madalas na maging sanhi ng error kapag kinopya mo ang lumang tutorial:

Lumang code (1.x) Bagong code (2.x)
entity.applyKnockback(dx, dz, h, v)entity.applyKnockback({ x, z }, v)
entity.runCommandAsync(cmd)entity.runCommand(cmd) — o system.runJob()
world.beforeEvents.worldInitializesystem.beforeEvents.startup
.slider("Label", 1, 10, 1, 5).slider("Label", 1, 10, { valueStep: 1, defaultValue: 5 })
.dropdown("Label", items, 0).dropdown("Label", items, { defaultValueIndex: 0 })
.textField("Label", "hint", "default").textField("Label", "hint", { defaultValue: "default" })
.toggle("Label", true).toggle("Label", { defaultValue: true })
effect.typeId → "speed"effect.typeId → "minecraft:speed"

Ang rows para sa applyKnockback, runCommandAsync, worldInitialize at effect.typeId ay galing sa @minecraft/server 2.0.0 overview ng Microsoft; ang apat na ModalFormData rows ay galing sa @minecraft/server-ui 2.0.0 changelog.

Lesson 5: Paano Pagdugtungin ang Behavior Pack at Resource Pack

Magkahiwalay ang manifest ng BP at RP. Para ma-activate ang RP kasabay ng BP mo, ilagay ang header UUID ng RP sa dependencies ng BP. Mapapansin mo na ang RP ay gumagamit ng module type na "resources".

📜 BP manifest (dependencies lang)
"dependencies": [
  { "module_name": "@minecraft/server",
    "version": "2.10.0" },
  { "uuid": "44444444-aaaa-4bbb-8ccc-444444444444",
    "version": [1, 0, 0] }
]
🎨 RP manifest.json
{
  "format_version": 2,
  "header": {
    "name": "Pinoy Legends RP",
    "description": "Textures at models",
    "uuid": "44444444-aaaa-4bbb-8ccc-444444444444",
    "version": [1, 0, 0],
    "min_engine_version": [1, 26, 50]
  },
  "modules": [
    { "type": "resources",
      "uuid": "55555555-aaaa-4bbb-8ccc-555555555555",
      "version": [1, 0, 0] }
  ]
}
🔗 Pansinin: ang uuid sa dependency ng BP ay eksaktong kapareho ng header.uuid ng RP (44444444-...), hindi ng module uuid nito. Subukan ito sa generator sa susunod na lesson!
